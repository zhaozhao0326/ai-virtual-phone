- **修复② 总 token 刹车**：`chat-engine.ts` 在 `assemblePromptPayload` 返回后读 `preset.openai_max_context`，按 (上限-2000 生成预留) 估算总 token，超出优先裁最旧聊天历史（系统/角色卡/记忆不动）

### 3.4 抓人设三连（1.7.6 → 1.7.8，dd482006 + 5a41e696）
- **★ 用户核心原则（必须遵守）**：抓人设 = 以内核设定为**锚点**让角色更准确地**活**着演绎；**绝不是**把内核写成死板规则/固定台词锁死角色。要的是**活人感**（自然、能即兴、有成长），不是木偶/傻子。固化=锚定稳定底盘，**不限制**角色对新情境的自然反应。
- **1.7.7（dd482006）**：
  - ① 世界书去随机门：`isWorldBookEntryActivated` 移除 `Math.random()` 概率分支 → 关键词匹配的条目永远激活，消除同卡同模型不同会话人设随机缺失
  - ② 核心记忆强化语气维度：`DEFAULT_CORE_MEMORY_PROMPT` 新增「保留角色标志性口头禅、语气词、说话节奏与风格特征」
- **1.7.8（5a41e696）角色身份块软锚定**：`getMarkerContent` 的 `charDescription` 末尾追加「角色演绎锚定」软指令——确立人设为稳定底盘（保持连贯一致），同时明确允许自然/灵活/即兴/有成长地回应，并点明「不要生硬照搬设定或背诵固定台词」。**是软指令不是硬锁，不动预设顺序**

### 3.5 文档导入世界书常驻修复（1.7.8 → 1.7.9，046d6711）
- 用户用法：从 Word 导入世界书教 AI 说话（如《Gemini别这么说》说话风格指南）
- **发现的坑**：`worldbook-doc-import.ts` 的 `buildWorldBookFromDoc` 生成条目 `constant=false` + `key=""`，而 `isWorldBookEntryActivated` 对空 key 直接 `return false` → **文档导入的世界书永不激活（静默失效）**
- **修复**：文档导入条目默认 `constant=true`（常驻），位置 `before_char`（角色设定前）不变
- **世界书激活/绑定关键语义（用户最关心的知识点）**：
  - 「谁看得到这本书」= 绑定管理（全局 vs 角色专属 `defaults.worldBookIds`），**常驻不会把它变全局**
  - 「常驻 constant」= 是否免关键词触发；说话准则/行为指南类 → 常驻；背景设定/场景规则类 → 关常驻 + 填关键词（剧情会自然提到相关词），省 token
  - 常驻代价：每轮全量注入，token 成本按文档长度计（该 docx 约 4k token/轮）

## 五、已知架构知识点

### 5.1 记忆系统（memory）
- 三层：短期上下文（short-term，按 token 预算截断）→ 长期记忆（long_term，`maxLongTermEntries=500` 超了删最旧，`autoSummarizeEnabled` 每 80 事件 LLM 总结）→ 核心记忆（core，`maxCoreEntries=50` 超了合并压缩，重建时提炼"角色是谁"+语气特征）
- 拼装后总 token 刹车在 `chat-engine.ts`（读 `openai_max_context`，超了砍最旧聊天历史）
- 总结依赖「记忆总结 API」绑定 `memorySummaryApiConfigId`，辅助 API 没配好总结会静默失败（角色显得"记性差"先查这个）
- 文件：`lib/memory-types.ts`、`memory-storage.ts`、`memory-service.ts`、`memory-summarizer.ts`、`core-memory-builder.ts`、`memory-embedding.ts`、`memory-injector.ts`、`short-term-assembler.ts`

### 5.2 世界书（world book）
- 配置：`lib/settings-storage.ts` 的 `WorldBookConfig`；条目 `WorldBookEntry`（key/constant/position/depth/useProbability/probability/insertion_order/role）
- 激活：`llm-prompt-assembler.ts:1303` `isWorldBookEntryActivated`——constant 直接 true；否则 key 逗号分隔、`use_regex` 决定正则/包含匹配；**空 key + 非 constant = 永不激活**（1.7.9 已让文档导入默认 constant）
- 组装：preset 驱动（`prompt_order` marker 决定位置），`charDescription` marker 在 `getMarkerContent`（397 行），角色卡/世界书/记忆按 preset 顺序注入
- 导入：角色卡 PNG/JSON 内嵌 `character_book` 自动导入并绑角色（`attachEmbeddedWorldBook`）；`worldbook-doc-import.ts` 支持 .docx/.doc/.txt 直接转世界书（UI：设置 → 世界书管理 → 从 Word / 文档导入）
- 绑定：`BindingSlot`（worldBookIds/voiceConfigId 等），`resolveBinding` 合并全局/角色

### 5.3 角色卡存储
- 本 App 角色卡：`lib/character-storage.ts`（`parseCharacterFromJson` 识别 chara_card_v2/v3 拆 data）
- 独家特调：`lib/mixology/types.ts` 的 `MixCharacterCard`（完全不同的类型系统，两套不互通）
- 酒馆 PNG 卡导入：`phone-character-app.tsx` `handleImportFile`（PNG/JSON 两分支统一走 `attachEmbeddedWorldBook`）

### 5.4 群管理动作
- 群聊走 `applyAIGroupAdminAction`；1:1 走 `applyAIOneToOneGroupAdminAction`
- 标签链路：模型输出 `[A动作]` → `rich-message-parser` → chat-room 派发；管道符格式 `[A 设置群公告|内容:xxx]`

### 5.5 WorkBuddy 沙箱限制
- 批量删除文件（超 50 个）会被 genie-safe-delete 拦截
- `next build` 清理 `.next` 会撞墙；绕法：`mv .next .next_old_xxx`
- 本地 docx 读取：editor_sdk `open_file` 是异步流，直接 `doc_resolve_document_structure` 会报 "document is not open"；兜底用 python zipfile 解析 `word/document.xml` 的 `<w:t>`
